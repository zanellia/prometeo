# SQP for MPC: prometeo vs acados

The optimal control problems of [`examples/sqp_mpc`](../../examples/sqp_mpc),
N = 20, input bounds:

- **cart-pole** ([`sqp_mpc.py`](../../examples/sqp_mpc/sqp_mpc.py)): nx = 4, nu = 1;
- **hanging chain** ([`chain_mpc.py`](../../examples/sqp_mpc/chain_mpc.py)):
  `n_free` masses connected by springs, the velocity of the last one as input;
  nx = 6 n_free + 3, nu = 3 (n_free = 1, 3, 5: nx = 9, 21, 33).

solved with:

- **prometeo**: the examples, transpiled to C. Gauss-Newton SQP; QPs solved by
  a primal-dual interior-point method (Mehrotra's predictor-corrector) written
  in prometeo, whose Newton steps are Riccati recursions; RK4 step and
  Jacobians generated by CasADi.
- **acados**: the same problems (one RK4 step per interval, Gauss-Newton,
  `PARTIAL_CONDENSING_HPIPM` with `qp_solver_cond_N = N`, i.e. no condensing),
  [`acados_sqp.py`](acados_sqp.py).

Both give the same solutions (to 5e-11, also in closed loop), which match
CasADi/IPOPT (`tests/test_sqp_reference.py`).

## Results

Intel i7-1370P, gcc 11.4, `-O2`. Times measured by each program (prometeo:
`main` without setup, best of 30 runs; acados: `time_tot`, best of 200 solves
for the full solve). RTI step: average over a closed loop of 30 steps.
acados uses BLASFEO built for `X64_AUTOMATIC` (AVX2 on this CPU); prometeo is
shown with BLASFEO built for `GENERIC` (the default of the repository and of
CI) and for `X64_INTEL_HASWELL` (AVX2).

Full SQP solve from zero:

| problem      | nx | acados  | prometeo `GENERIC` | prometeo `HASWELL` | QP iterations (acados / prometeo) |
|--------------|----|---------|--------------------|--------------------|-----------------------------------|
| cart-pole    | 4  | 2.0 ms  | 3.4 ms             | 3.1 ms             | 56 / 79                           |
| chain, 1 mass| 9  | 2.3 ms  | 6.5 ms             | 2.9 ms             | 42 / 55                           |
| chain, 3     | 21 | 3.3 ms  | 19.6 ms            | 5.2 ms             | 32 / 49                           |
| chain, 5     | 33 | 8.3 ms  | 47.7 ms            | 10.1 ms            | 43 / 49                           |

RTI step (one SQP iteration per sampling time):

| problem      | nx | acados  | prometeo `GENERIC` | prometeo `HASWELL` | QP iterations per step (acados / prometeo) |
|--------------|----|---------|--------------------|--------------------|--------------------------------------------|
| cart-pole    | 4  | 226 us  | 264 us             | 235 us             | 5.7 / 6.7                                  |
| chain, 1 mass| 9  | 290 us  | 563 us             | 245 us             | 4.1 / 4.6                                  |
| chain, 3     | 21 | 617 us  | 1920 us            | 533 us             | 5.0 / 5.1                                  |
| chain, 5     | 33 | 1247 us | 5455 us            | 1173 us            | 5.9 / 5.8                                  |

With the same BLASFEO target, the prometeo solver is as fast as acados per RTI
step, and within 1.2 - 1.6x for the full solve (where it takes more QP
iterations: HPIPM's initialization and step rules differ from those of the
example). For the small cart-pole, the overhead of many small BLASFEO calls
dominates; for larger systems the time goes into BLASFEO's kernels (95% of the
time for the chain with 3 masses), so the BLASFEO target matters most: the
`GENERIC` kernels are 4 - 5x slower than the AVX2 ones at these sizes.

## Running

```
benchmarks/sqp_mpc/time_prometeo.sh [cartpole | chain [n_free]] [python]
```

(set `BLASFEO_LIB` to the directory of another `libblasfeo.so` build to time
it with that one) and, with acados installed (`ACADOS_SOURCE_DIR` set, `acados_template`
installed), from a scratch directory (acados generates code there):

```
python <prometeo>/benchmarks/sqp_mpc/acados_sqp.py [cartpole | chain [n_free]] [repetitions]
```
